# 搜索结果与统一 spill

## 当前实现

普通工具、网页搜索和本地资源搜索都由 `AgentRuntime → spill_tool_output` 统一处理，不建立独立的搜索落盘流程。

- `search_output.py`：从网页结果或 Skill 中抽取查询词附近的原文，生成结构化文本段；只负责相关性，不写文件、不调用摘要模型。
- `ToolResult.preview / sections`：可选的预览说明与文本段；原始完整文本继续保存在 `text`，图片字段不变。
- `spill.py`：统一判断限额、脱敏、保存原始文本、生成可分页正文/索引和返回预览。普通工具继续使用头尾预览；搜索使用相关性预览。

原有 `search_resources()` 函数仍返回 JSON，保持直接调用契约；工具路由将其包装为搜索视图。Web 只适配已配置 `web` MCP 的 `search` 工具、且结果为已识别的 JSON；其他 MCP、错误、图片和未知结构不强行改写。未修改独立 Web MCP 或 DeepSeek 服务。配置的 `web.search` 在本地路由中向远端传 `limit=50`；调用者的 `limit`（默认 5，1–50）仅用于本地详细展示条数，普通和增强模式均生效，实际返回数仍取决于上游。工具 schema 的本地说明同步这个语义，不改变其他 MCP。

## 提示词

取消“专业任务必须先查 Skill”。主子 Agent 及 search_resources schema 改为仅在认为有必要时查询，例如用户指引或缺少资源；已有上下文足够就继续，不重复查询。知识库仍未建立。

## 返回布局

本地 Skill 未超限：

1. 所有结果的标题/URL 或说明路径、命中摘录、正文视图行号。
2. 完整段落（不再放入转义换行的单行 JSON）。

超限（以及启用 spill 时的所有已识别网页搜索结果）：

1. 查询、来源、候选数和有界的相关原文摘录，保留上游排序，不让第一条正文淹没后续结果。
2. spill 返回三个文件定位：
   - `<id>.log`：完整原始输出（脱敏），保留 JSON 结构；不是 MCP 网络字节原包。
   - `<id>.index.txt`：所有候选的完整索引、摘录与正文行范围。
   - `<id>.view.txt`：按候选展开的完整正文、上游片段/摘要或 Skill 说明，长行按显示宽度折行。
3. 使用现有 `read_file`，对正文视图指定 offset 和较小 limit（如 10），避免读取结果再次超限。正文行号指视图，不指原始 JSON。

索引与视图均在统一 spill 中生成；不是绕过 spill。Skill 原先的 20000 字符静默裁剪已移除，由 spill 统一限制和保存。

## 摘录规则

- 英文标识符保留，中文使用连续词组及有限的重叠双字词；常见虚词过滤，无额外依赖或语义摘要模型。
- 每条最多三个窗口，每个命中前后默认约 200 字符，避免重叠窗口，优先覆盖不同查询词；截取点附近最多向外扩展 60 字符，尽量补全句子。网页由 `mcp.web.search.context_chars` 控制，本地 Skill 使用代码默认值 200。
- 网页从 content 或 snippet 找字面命中；上游 summary 单独标注，不冒充原文。
- 网页前 `limit` 条使用原有详细摘录；其余使用无模型的抽取式简览：分句、按不同查询词覆盖评分、挑选 1–2 个相关原文句子并去重，按原文顺序输出，每条原文简览最多 200 字符（含省略号，不含标题/URL/标签/定位）。英文关键词按标识符边界匹配，中文按子串匹配；过滤明显标题、导航、公式和参考文献条目。无命中回退可用原文并明确标注；无可用正文/片段也明确标注，不使用生成的上游 summary 冒充原文。不增加 API 调用、模型或第三方依赖。
- 无字面命中不丢弃结果，标明情况并提供来源开头；原有排名不变。
- Skill 元数据匹配原因与正文字面命中分开，不把 references 当作已经搜索的全文。摘录仅用于选 Skill，执行前仍需读取完整说明。
- 不同来源文本视为数据，不得提升为 Agent 指令。

## 限额

配置：

```yaml
spill:
  max_inline_chars: 20000
  max_preview_chars: 24000

mcp:
  remote_windows:
    url: http://127.0.0.1:8767/mcp
  web:
    url: http://127.0.0.1:8766/mcp
    search:
      context_chars: 200
```

与既有行数/行长限制同时生效，普通工具也受总字符限制。本地 Skill 搜索预览按上游顺序装入完整条目：前最多 10 条含完整摘录，其余仅说明路径与正文定位。网页预览先按顺序为全部候选装入短句简览，再为前 `limit` 条均分可用详情预算展示摘录（不再固定为 10 条），过长摘录明确标注预览省略。网页详细摘录可在预算内缩短，标题、URL 和定位不截断；简览放不下退为紧凑条目；紧凑条目也放不下则停止并提示读取完整索引。不截断标题/URL，不重排候选。文件路径回执计入预览预算。

`mcp` 每个服务必须包含 `url`，不再支持 URL 字符串简写。`web.search.context_chars` 必须为正整数，仅用于本地网页搜索结果展示，不传给 MCP，也不影响本地资源搜索；关闭/移除 web MCP 时不参与检索。

`spill.enabled=false` 时普通工具和本地 Skill 保持原有不落盘/不限额语义；网页搜索仍遵守详细/简览展示和总预览预算，不自动暴露全部正文，并明确标注落盘关闭、全文文件不可用。文件保存失败明确报错，不声称全文可恢复。所有衍生视图先脱敏，正则脱敏仍只是启发式，不应当作完整凭据防泄漏方案。

## 边界与后续

- 本轮没有改 search_resources 的目录规则、profile、知识库，也没有改 Web 搜索后端或重新排序结果。
- 未增加字符分页工具；本次搜索通过正文视图解决单行分页，其他任意长行仍可后续补充保底读取。
- 本次改动仅在 `chat_ai_test`，通过本地单元测试和既有结果离线回放验证；不新增付费搜索，不合并、部署或重启正式服务。
